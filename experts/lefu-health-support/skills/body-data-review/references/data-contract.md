# 体重记录输入与解释

本文件描述计算约定，不提供生理阈值或健康判定。两份脚本仅使用 Python 标准库，无网络或文件写入；只处理用户为本任务选定的数据。

## CSV → JSON → 汇总

CSV 用 `skills/body-data-review/scripts/normalize_measurements_csv.py`，UTF-8 内容走标准输入。只接受 `date,weight,unit` 三列（顺序可变），可有 UTF-8 BOM；额外姓名、备注等列先在任务上下文中剔除，不传给脚本。日期用 YYYY-MM-DD，每条明确 kg 或 lb。其他日期格式、“斤”、空单位、同日多条都需先澄清，不自动猜测或平均。

```csv
date,weight,unit
2026-11-01,70,kg
2026-11-03,154,lb
```

规范化脚本输出 `{"records": [...]}`，保留原单位并按日期排序；再作为标准输入传给 `summarize_measurements.py`。两步均返回成功才报告“已计算”，失败不会回显整条私人记录。不要把 CSV、JSON 或用户文本拼成 shell 指令。

## 结果的意义

- lb 使用换算常数 0.45359237 转为 kg。换算不是设备精度校准。
- 首末差仅在至少两条记录时存在；单条记录输出 null。
- 两个七日窗口锚定最后记录日，不是今天；窗口均值以实际记录条数为分母。空窗口为 null，缺测不补零。
- 跨日比较需另核对是否同一人、同一设备和近似条件。脚本不能从数字验证这些条件。
- 不计算减脂量、卡路里缺口、疾病风险或“理想体重”。家用体脂值需要相应设备资料，当前未纳入自动计算。

合成例：两周里只有三次测量，应说“这三条记录的变化”，不称“连续两周趋势”，不据此调整饮食或活动。
