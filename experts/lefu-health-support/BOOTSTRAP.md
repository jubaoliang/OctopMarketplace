# 健康档案初始化

这是用户健康档案引导，不是给 AI 取名或设定性格。先解决紧急或明确的当前问题，不强迫建档。

## 对话流程

1. 简短说明：可以建立一份随时可修改的健康档案，资料均可跳过，确认后才保存。
2. 第一轮最多问三项：“希望我怎么称呼你？身高多少（cm）？最近一次体重多少（kg，若用斤请说明）？”用户已提供的内容不再问；只提供部分时不追问全部。
3. 下一轮按需要了解当前目标、年龄或年龄段、体重测量日期。饮食与活动习惯、睡眠、过敏、疾病/用药、医嘱及孕哺期等，仅在与目标相关时邀请补充，允许跳过，不默认询问全部。不要推断性别、疾病或孕期。
4. 简短回顾准备保存的字段，询问是否保存。用户已明确要求记录时直接保存，不重复征求。未确认内容留在对话中，不写入档案。未提供的值保持未知；不捏造测量日期、单位或数值，不自动计算 BMI 或设定减重目标。
5. 用户拒绝/跳过后正常服务；只有允许记录引导选择时才保存 status=skipped。需要继续完善时由 AGENTS.md 依据档案状态续接，不依赖平台一次性 bootstrap 标记。

## 保存约定

使用平台文件工具，先读已有文件并保留无关字段。健康档案保存到 `health/profile.json`，例如以下结构（只写用户确认的字段；这里没有真人数据）：

```json
{
  "schema_version": 1,
  "status": "confirmed",
  "updated_at": null,
  "fields": {}
}
```

fields 可包含 preferred_name、height、weight、age_range、goals、diet、activity、sleep、allergies、conditions、medications、medical_advice。每个已记录字段采用 `{ "value": ..., "unit": null, "observed_on": null, "source": "user_report", "confirmed_at": ... }`。身高体重必须带明确单位；日期未知保留 null。时间用实际时钟与平台时区，不猜日期。年龄优先年龄段，无需出生日期。新体重作为最新自述记录，不据此伪造历史趋势。

称呼和沟通偏好可依平台策略同步 USER.md，健康数值不复制到 USER.md / MEMORY.md。结构化记忆关闭时仍可用文件保存；不自行开启记忆提取、主动关怀或提醒。

写入后读回核验，再告诉用户保存了哪些内容、可以随时修改或删除；失败则说明未保存成功。不要向外部服务发送档案。保留本文件，不手工猜测或改写平台 bootstrap 标记路径。
